# Аудит використання AI (Лабораторна 1)

**Промпт:** Згенеруй spec.md для Event-driven Telegram CMS (Шлях Bottom-Up).

**Результат AI:** Згенеровано ER-модель та архітектуру модулів.

**Топ-3 зрізані кути (Trade-offs), які запропонував AI:**
1. **Авторизація без ролей (RBAC):** AI запропонував таблицю `Users` без поля `role`. Усі зареєстровані користувачі мають права адміністраторів, що є небезпечним "зрізаним кутом" для масштабування.
2. **Зберігання медіа:** Замість інтеграції з хмарним сховищем (S3), AI запропонував зберігати просто `media_urls` (Array). Це перекладає відповідальність за хостинг файлів на клієнта.
3. **Обробка черг (Retry Policy):** Критерії прийняття AI кажуть, що при помилці Telegram API пост просто переходить у `failed`. Відсутня архітектура "Exponential Backoff" (повторних спроб через зростаючі інтервали часу).

# 2.1 PostgreSQL та драйвер postgres

* Статус: прийнято
* Дата: 2026-11-18

## Контекст і постановка проблеми
Вирішення яка база даних використовуватиметься для нашого проєкту

## Decision Drivers
* простота
* вимоги курсу
* контроль атомарності

## Розглянуті варіанти
* Варіант 1: PostgreSQL + драйвер postgres (сирий SQL)
* Варіант 2: ORM
* Варіант 3: Query Builder

## Порівняння варіантів
### Варіант 1
* Добре, тому що я вже активно працюю з PostgreSQL, добре розумію всю логіку та вже набила руку.
- Прямий контроль над SQl запитами.
- Наглядно видно які саме запити виконуються.
- Легше уникнути прихованих проблем.
* Погано, тому що доводиться писати однотипні запити для всіх базових операцій.
- Ризик SQL ін'єкцій при неправильному виконанні конкатенації
- Щоб змуніти СУБД потребується більше змін ніж в ORM

### Варіант 2
* Добре, тому що вимагає написання менше коду, через безпосередній зв'язок реляційної бази даних з об'єктно орієнтовним кодом. 
- Більший рівень захисту від SQL ін'єкцій.
- Можна легко змінити тип СУБД з мінімальними змінами в коді.
* Погано, тому що складно відстежувати які саме SQL запити відправляються до БД.
- Часто зустрічається проблема N+1.
- Потребує глибокого розуміння логіки ORM та сворення через неї викликів SQL, щоб не обвалити БД

### Варіант 3
* Добре, тому що є можливість змінити СУБД без змін у коді.
- Динамічна побудова запитів.
- Ланцюг методів легкий для читання
* Погано, тому що не завжди видно кінцевий SQL запит.
- Підтримує тільки базовий функціонал специфічних СУБД
- Специфічний синтаксис, на вивчення якого треба витрачати час

## Обране рішення
Обрано PostgreSQL з драйвером postgres, тому що для моїх потреб в даному проєкті цього цілком достатньо. З моїм рівнем знань та досвідом роботи, однозначно легше працювати з SQL.

## Наслідки
* Позитивні: Швидкий старт, без витрат часу на набуття навичок роботи з ORM.
Повний контроль та передбачуваність, оскільки все роблю я вручну.
Проста архітектура в БД.
* Негативні: Збільшення витрат часу на написання шаблонного коду.
Потреба більше приділяти часу безпеці проєкту

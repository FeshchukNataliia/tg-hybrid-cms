# Специфікація: Telegram Hybrid CMS (Lab 3)

## 1. Що і Навіщо (Мета)
Гібридна CMS для створення та керування контентом Telegram-каналів. Мета етапу Lab 3 — побудувати відтворювану піраміду автоматизованого тестування (Unit, Integration, E2E) та перевірити реальну ефективність тестів за допомогою мутаційного тестування.

## 2. Архітектура та Межі (Модулі)
- **Шари:** `Routes → Services → Repositories`, `EventBus → Worker`, `AsyncLocalStorage`, PostgreSQL (`postgres`), конфіг через `.env` та відкладений пул БД.
- **Схема БД:** `users (id, username, created_at)`, `posts (id, user_id, title, content, status: draft|queued|published|failed, created_at)`. *(Сутності `Channels`, `QueueJobs`, `content_payload` відкладено у V2).*
- **API та помилки:** `POST /posts` (201 / 400), `GET /posts` (`LEFT JOIN`, без N+1), `POST /posts/:id/publish` (ідемпотентно `draft → queued → published|failed`, 200 / 400 / 404), `GET /version` (200).

## 3. Критерії прийняття 3 лаби
- Усі 3 рівні тестів (Unit, Integration, E2E) налаштовано і працюють стабільно.
- Покриття цільового модуля перевіряється за гілками (`branches`), а не лише за рядками (`lines`).
- Одна команда `make test` автоматично піднімає інфраструктуру (Docker/БД, ініціалізацію таблиць) і проганяє всі тести.
- Команда `make mutation` відтворює мутаційне тестування та формує звіт.
- Проведено аудит топ-3 місць, де «зелені» тести пропускають реальні баги, та виконано підсилення тестів окремими комітами.

## 4. Стратегія тестування (Scope Lab 3)
- **Unit-тести (повне покриття гілок):** цільовий компактний модуль `src/services/post.service.js` — покриття 100% гілок (`if/else`, граничні значення, помилки) із мокуванням залежностей.
- **Інтеграційні тести:** взаємодія HTTP-шару, сервісів і репозиторіїв з реальною БД PostgreSQL (у Docker: створення, `LEFT JOIN`, атомарний `UPDATE`, коди `400/404`).
- **E2E-тести:** повний наскрізний сценарій користувача — створення чернетки поста → перевірка у стрічці `GET /posts` → публікація → підтвердження фінального статусу та ідемпотентності повторного запиту.
- **Мутаційне тестування:** прогін StrykerJS для цільового модуля, звіт із класифікацією вижилих мутантів (реальна прогалина / еквівалентний / прийнятний).

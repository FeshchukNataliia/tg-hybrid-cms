# Захист Лабораторної №2

## 1. Що і навіщо
Реалізовано ядро бекенду для гібридної CMS: інтегровано ізольовану PostgreSQL (Docker), створено наскрізне логування бізнес-процесів (Trace ID) та реалізовано Event-Driven архітектуру для фонової публікації постів.

## 2. Топ-3 розбіжності / "зрізані кути" (проти spec)
1. **In-Memory Воркер замість зовнішньої черги:** Для спрощення інфраструктури V1 фоновий воркер реалізовано через вбудований `node:events` (EventBus), а не через Redis/RabbitMQ. 
*(Коміт: [c9acbf9])*

2. **Захардкоджений User ID:** Оскільки модуль авторизації (JWT) ще не реалізовано, ініціатор запиту (`userId: 1`) жорстко зафіксований на рівні middleware. 
*(Коміт: [e7f1033])*

3. **Graceful Shutdown на рівні сервера, а не PM2/Docker:** У V1 ми перехоплюємо падіння БД на рівні `server.js`, хоча в Enterprise це робить оркестратор. 
*(Коміт: [2cb3933])*

## 3. Ключове рішення
**Використання AsyncLocalStorage для Trace ID.** 
Замість передачі `traceId` параметром через усі шари (Prop Drilling) або впровадження важких DI-контейнерів, використано нативний модуль Node.js для ізоляції контексту запитів (навіть при передачі завдань у воркер).
Деталі: [docs/adr/0001-use-async-local-storage-for-trace-id.md](./docs/adr/0001-use-async-local-storage-for-trace-id.md).

## 4. Перевірка
- **Запуск БД:** `docker compose up -d` -> База піднята на порту 5435.
- **Запуск API:** `node src/server.js` -> Сервер працює, логи з Trace ID виводяться в консоль.
- **Тести:** `node --test test/smoke.test.js` -> Smoke-тест проходить успішно.
- **Версія:** /version: [5653608]
